## [Unreleased]

### Added (Chad's 2026-11-24 spot-check of 990c8a7: accepted answers and the M4 verifier gate)
- `answer_accepted` step event: when the verifier accepts a final answer the loop records it on that step, with `claims` and `citations` counts (before, only `answer_rejected` was recorded, so acceptance was implied by the run's status). An answer accepted at or after the deadline gets `answer_accepted` and then `answer_after_deadline`, and the run still ends `budget_exhausted:deadline`. Event names `ANSWER_ACCEPTED_EVENT` and `ANSWER_AFTER_DEADLINE_EVENT` live in `trace.schema`; the loop's `ANSWER_ACCEPTED`/`ANSWER_AFTER_DEADLINE`/`ANSWER_REJECTED` refer to them.
- `agentic_research.trace.gate.require_citations_verified(trace) -> RunConfig`, the check the M4 runner will call before it scores a trace's answer or citations. It raises `TraceGateError` with a `GateRefusal` code unless the run span has exactly one `run_config` event and it is the first (`no_run_config`, `duplicate_run_config`, `run_config_not_first`), it is a valid `RunConfig` (`invalid_run_config`) with verifier `citations` (`not_citations_verified`: `accept-all`, `custom:*`), and the step events agree with the status: an answered run has exactly one `answer_accepted`, on its last step (`answer_not_accepted`, so answered traces from before 2026-11-25 are refused), and any other run has none, except a `budget_exhausted` run whose last step was accepted too late (`answer_after_deadline`) (`acceptance_mismatch`). The gate re-checks the shapes `Trace` validation already refuses, so it also holds for a trace built with `model_construct`. It records configuration, not correctness: a custom class can still declare `label = "citations"`.

### Added (Chad's 2026-11-23 spot-check: the trace records the verifier)
- `run_config` event on the run span, written at 0 s by every `AgentLoop.run_traced` run: `RunConfig` with `verifier`, `corpus` (`corpus_id`, `retrieval`; `null` without a corpus), `seed` (the executor's retry-jitter seed, now `ToolExecutor.seed`), `step_timeout_s` and `budgets` (all six `Budgets` limits, `ConfiguredBudgets`; the v1 `budget_limits` field keeps its four). Before, an `accept-all` run's trace looked identical to a citation-verified one; the corpus, mode and verifier were only printed. This is the `run_config` part of M2 MINOR-5 (the `budget_counters` event and `backoff_s` on failed attempts are still open).
- The verifier label comes from the verifier's class: `label` class attribute (`AcceptAll.label = "accept-all"`, `CitationVerifier.label = "citations"`), else `custom:<class qualname>` (`agent.verifier.verifier_label`, at most 200 chars). It is read from the class, so an instance attribute cannot relabel a verifier. It records configuration; it is not an attestation. `RunConfig.citations_verified` is the check M4's runner will use (PLAN M4 acceptance: score only `citations` traces; refuse or flag the rest, including traces with no `run_config`).
- `AgentLoop.run_traced(corpus=CorpusConfig(...))`; `arp run --index` passes the backend's corpus id and retrieval mode. `Trace.run_config` returns the parsed event, or `None` for traces written before it existed (they still read).
- `arp trace show` prints the run's `config:` line (verifier, corpus and mode, seed, step timeout, per-tool and repair limits) instead of the raw event, and `config: not recorded` for older traces.

### Added (M3: `arp run` over a corpus)

The trace's run span has `provider=none` and no model. `--script` now applies to `--provider scripted` only; mixing the two files exits 2.
- `arp tools schema` lists every built-in tool: `calculator`, `search_corpus`, `read_document`. The research tools are bound to `NoCorpusBackend` (`tools.builtin.catalog_registry`) for export; their schemas do not depend on the corpus, and any call through that backend fails `permanent/backend_error`.

### Added (M3 citation verifier)
- `final_answer` claims: `FinalAnswer.claims` is a tuple of `Claim(text, citations)`, each `Citation(doc_id, start, end, quote, content_hash=None)` pointing into the normalized stored text (the offsets `search_corpus` and `read_document` return). The models check shape only (non-empty quote, `end > start >= 0`, sha256-shaped hash).
- `agentic_research.citations.CitationVerifier(backend)`, a `Verifier` for the loop's hook. It accepts an answer only if there is at least one claim, every claim has a citation, and every citation passes, checked in order: known `doc_id` (else `invalid_citation`), `content_hash` equal to the stored version when given (else `stale_source`), `quote == text[start:end]` exactly (else `invalid_citation`), and `[start, end)` inside text shown in full in this run for that version (the run's `EvidenceStore`; else `ungrounded_citation`). No claims or an uncited claim is `no_citation`. The verdict reason is the first issue; the message lists every issue by position (`claims[0].citations[1]`) with offsets and observed ranges only, never document text, so feedback is not evidence. Document lookups run in a worker thread, so the step timeout and deadline bound a slow backend; a backend failure other than an unknown doc id ends the run `failed:verifier_error`. `check_citations` and `feedback` are the pure parts. Correctness of the answer is left to the M4 graders.
- `evidence_dropped_truncated` step event (`tool`, `shown`, `dropped`) on every tool step whose evidence result returned spans the policy was not shown in full: passages cut from a search observation, a truncated `read_document` slice, or a result that got no observation at all (Chad's spot-check item 3: such a step was already counted in `EvidenceStore.dropped`; it is now visible in the trace too). `step_evidence(step, observation)` is the per-step rule both the store and the loop use. A successful result under an evidence tool's name whose output does not fit that tool's model (a foreign tool registered as `read_document`) gets an `evidence_unreadable` event instead of crashing the loop; the verifier then ends the run `failed:verifier_error`.
- Tests (42 new): table-driven verifier checks (valid, valid with hash, off-by-one start and end, quote not the stored text, past the end, unknown doc id, stale hash, stale beats a wrong quote, unobserved document, outside and straddling the shown range); `no_citation` cases; issue order and message format; feedback leaks no document text; capped lists; tampered stored text (`stale_source` with the old hash, `invalid_citation` without, old-version evidence does not ground). In the loop: an oracle search-read-answer run is accepted on the fixture backend and `RagEngineBackend` (lexical, hybrid); an answer citing unread text is rejected with feedback, repaired by reading it, then accepted; citations of omitted passages of a cut k=10 search are `ungrounded_citation` while shown ones are accepted, with the trace event; an elided-but-shown span grounds; answering a hybrid nonsense query is rejected (`no_citation`, then `ungrounded_citation`) and ends `budget_exhausted:repairs`, not `abstained`; truncated reads and results without observations appear as trace events; a slow backend ends `failed:verifier_timeout`, a broken one `failed:verifier_error`; a foreign tool under an evidence name gives `evidence_unreadable`. Model shape checks for `Citation`/`Claim`.

### Changed (Chad's spot-check of d670ed4: omitted passages are located)
- The `search_corpus` omission marker now lists the omitted passages' `(doc_id, start_char, end_char)`, best first, after the count: `...[2 passages omitted; read_document(doc_id, start, end): (0123456789abcdef, 0, 2400), (0123456789abcdef, 2401, 2600)]`. It carries no passage text, so it is not evidence; a policy shown no passage at all can fetch the passages with `read_document` (a passage longer than 1500 chars takes more than one read). The marker now counts against `max_chars`, so a passage-cut observation never exceeds the limit: locators that do not fit are counted as `+M more`, and the marker shrinks to the bare `...[N passages omitted]` before another passage is dropped. If not even the passage-free result plus the bare marker fits, the generic character cut applies as before. `passages_marker(omitted, locators=(), room=None)` returns `None` when nothing fits in `room`.
- Tests (10 new, 5 rewritten): exact markers with locators, `+M more`, the bare-marker fallback, a first passage too long (shown 0, both located, no text), defensive locator handling, and the hypothesis property now also checks the whole observation stays within `max_chars`, the listed locators are the leading omitted passages, and the marker is the longest that fits. The k=10 run over the fixture backend and `RagEngineBackend` (lexical, hybrid) checks every omitted passage is located. New: a run whose search shows no passage (a 2400-char first passage) reads both omitted passages back from the marker's locators, and only those reads ground them; a CitationNeeded index built with its default chunking (256 tokens) over prose made from the fixture corpus (about 5.6 chars per token) shows its best passage (242 tokens, 1336 chars) in full in the default 2000-char observation (1828 chars with the marker). Denser text can still overflow, in which case the marker locates the passage. A step with a result but no observation counts nothing for both `search_corpus` and `read_document` (test parametrized).

### Changed (M3 grounding: only text shown in full is evidence)
- ADR-0004 amendment (2026-11-19, Bogart's patch), mirrored in PROJECT_SPEC and PLAN M3: the agent abstains only through `GiveUp` (never on "no hits"; hybrid search always returns `k` neighbours), the verifier rejects ungrounded answers, exhausted repairs are graded as not abstaining, any score floor is per search mode and frozen on `dev`, and `answered_when_unanswerable` / `abstained_when_answerable` are reported side by side. A span grounds a citation only if the policy was shown it in full; elision keeps evidence. New PLAN M3 acceptance checks for both rules.
- `ObservationShaper` cuts a successful `search_corpus` observation at passage boundaries: it renders the longest prefix of passages that fits in `max_chars`, drops the rest whole with `...[N passages omitted]`, and records `Observation.shown_passages` (new field, kept on elision; only on tool observations). No passage is cut mid-text. If even the passage-free result does not fit, the generic character cut applies with `shown_passages = 0`. Other tools are unchanged.
- `EvidenceStore` now reads each step's observation: `EvidenceStore.from_steps(steps, observations)` (observations required) and `EvidenceStore.from_state(state)`; `add_step(step, observation)` replaces `add_result`. Only the shown passages of a search count; a `read_document` slice counts only if its observation was not truncated; a result without an observation counts nothing; `EvidenceStore.dropped` gives the spans per step that were returned but not shown in full. This removes the known limit recorded on 2026-11-18 (a truncated observation used to count its full span).
- Tests (25 new): passage-boundary cuts (fit, mid-list, singular marker, first passage too long, envelope too long, elision, non-search tools) and a hypothesis property (whole passages in order, prefix within the limit, maximal); evidence from cut searches, truncated reads, missing, elided and mismatched observations; a k=10 search over the fixture backend and `RagEngineBackend` (lexical and hybrid) where nothing past the cut counts; a hybrid nonsense query that returns 5 passages and ends `abstained` only because the policy gave up; a 1500-char prose `read_document` slice fits the default observation while a quote-heavy one is truncated and adds nothing.

### Added (M3 research tools)
- `search_corpus` (`agentic_research.tools.search.SearchCorpusTool`): top-`k` passages (default 5, at most 50, optional exact-match `filters` on `doc_id`/`source`) from a `SearchBackend`, each with `doc_id`, `chunk_id`, `source`, `content_hash`, `page`/`page_end`, normalized `start_char`/`end_char`, `text`, `rank` and `score`, plus the `corpus_id`. A whitespace-only query is `invalid_args/blank_query` (the backend is not called); a `BackendError` is `permanent/backend_error`; anything else the backend raises is a crash (`permanent/tool_crashed`), not the model's fault. It accepts exactly the arguments of M1's probe stub; the probe keeps its own frozen stub schema (pinned by sha256 in a test) so `probes/tool_calls.v1` stays reproducible.
- `read_document(doc_id, start, end)` (`agentic_research.tools.read.ReadDocumentTool`): `text[start:end]` of the stored normalized document with `doc_id`, `source`, `content_hash`, the actual offsets and `doc_length`. At most 1500 characters per call (`MAX_READ_CHARS`, below the observation shaper's default 2000); `end` past the document is clamped; `start` past it is `invalid_args/start_out_of_range`; an unknown doc id is `invalid_args/unknown_doc_id`.
- Both tools run the backend call in a worker thread (`asyncio.to_thread`), so a CPU-bound search does not block the event loop. A timed-out call cannot stop its thread: it finishes in the background and its result is dropped. `research_registry(backend)` builds `calculator` + both tools; `default_registry()` is unchanged (no corpus).
- `agentic_research.evidence.EvidenceStore`: the spans a run observed, built from its recorded steps (`EvidenceStore.from_steps(state.steps)`), so only results the loop accepted count; a timed-out, failed, or budget-refused call adds nothing. Spans are keyed by `(doc_id, content_hash)`; `covers(doc_id, content_hash, start, end)` checks a range against the merged (overlapping or touching) observed spans. (Superseded the next day: see "M3 grounding" above.)
- Tests (73 new): both tools through the real registry and executor on the fixture backend and `RagEngineBackend` (lexical and hybrid): passages equal the backend's, slices equal the stored text, clamping, the exact maximum range, table-driven schema and range rejections, backend errors, crash classification, worker-thread execution, a blocked search that times out; evidence interval merging and `covers` edge cases, version keying, an oracle run (search, read, calculator, failed read, answer) over both backends, and a timed-out search that is not evidence even after its thread returns.

### Added (M3 search backends)
- `agentic_research.backends`: the search backend contract the M3 research tools and citation verifier will use. `Passage` (rank, score, `doc_id`, `chunk_id`, `source`, `content_hash`, `heading_path`, `page`/`page_end`, normalized `start_char`/`end_char`, `text`; validated: finite score, `len(text) == end_char - start_char`, page range), `StoredDocument` (normalized text whose sha256 must equal `content_hash`), the `SearchBackend` protocol (`corpus_id`, `search(query, k, filters)`, `document(doc_id)`), `make_doc_id` (`sha256("<corpus_id>:<source>")[:16]`), and `parse_search_payload`, which reads a CitationNeeded `search --json` payload: it requires `schema_version` 1 (an unknown or missing version is a `BackendError`, never an empty hit list), reads `hits`, and requires every format-2 citation field on each hit.
- `RagEngineBackend` (`agentic_research.backends.rag_engine`) over a CitationNeeded format-2 index directory through its in-process API: refuses any `format_version` other than 2 before loading, lets `load_index` re-check chunk offsets against `documents.jsonl` (a tampered index is refused), refuses documents from any corpus but the explicit `corpus_id`, and builds its hits through the same `search --json` payload. `mode="lexical"` (BM25) by default, `mode="hybrid"` (RRF over the index's dense and BM25 retrievers).
- `FixtureSearchBackend`: keyword search over in-memory documents (paragraph passages, distinct-term score, deterministic ties) with the same contract, so unit tests need no index build.
- Fictional fixture corpus `tests/fixtures/corpus/rabbithole-tasks-v1/` and `tests/rag_index.py`, which builds a format-2 index from it with CitationNeeded's own ingest, chunking and `save_index` (hashing embedder: no model, no network).
- Tests: one contract suite run on the fixture backend and on `RagEngineBackend` in both modes (citation offsets resolve into the stored text, `content_hash`, doc ids, ranks/scores, `k`, filters, bad arguments, unknown doc ids); the pinned doc id `sha256("rabbithole-tasks-v1:bridges/velmora-bridge.md")[:16] == 7610eae52aac886e`; in-process results equal `rag-engine search --json` on the same index in both modes; table-driven payload, `Passage`, format-version, foreign-corpus and tampered-index rejections.

### Fixed (Chad's M2 re-check at 1200762)
- N-1: a fired time limit is now final. Before, the loop only looked at `scope.expired()` inside `except TimeoutError`, so a policy or verifier that caught the cancellation and returned had its result counted (Chad's probe: `succeeded` at ~0.7 s with a 0.2 s step timeout), and one that caught it and raised something else was `failed:policy_error`/`failed:verifier_error`. Now `AgentLoop` checks `scope.expired()` after every timed policy and verifier call: whatever comes back after the limit fired ends the run as `budget_exhausted:deadline` (deadline bound) or `failed:policy_timeout`/`failed:verifier_timeout` (step timeout, error class `timeout`), with a `late_result_ignored` step event (`outcome`: `returned` or `raised <name>`). Usage a late `Decision` or `PolicyFailure` reports is still charged and its provider calls still traced. `ToolExecutor` does the same per attempt: a late output, `ToolFailure` or crash is `tool_timeout` (or the deadline error when the deadline cut the attempt), and is retried like any timeout. Code that swallows the cancellation and keeps running is not cancelled again; ADR-0006 now says so.
- README and CHANGELOG no longer say `arp run` never overwrites a trace: it refuses an existing file before the run, but does not yet publish with an exclusive create (M2 MINOR-1, open).

### Fixed (Chad's M2 review at f36a6c4)
- MAJOR-1: the verifier hook is now bounded like the policy: it runs under `asyncio.timeout` of the step timeout or the time left before the run deadline, whichever is shorter. If the deadline fires the run ends `budget_exhausted:deadline`; if the step timeout fires, `failed:verifier_timeout` (run error class `timeout`). A verifier that raises its own `TimeoutError` is `failed:verifier_error`. An answer whose verification ends at or after the deadline is not honoured (`budget_exhausted:deadline`, `answer_after_deadline` step event), and an answer chosen after the deadline is not verified. Before, a 1.5 s verifier with a 0.3 s deadline ended `succeeded`.
- MINOR-4: tokens from a reply that fails to parse are charged to the token budget. `PolicyFailure` has a new `tokens` field (validated `int >= 0`), `LLMPolicy` sets it from the reply's usage, and the loop charges it, so the run span's `budget_used.tokens` now matches its provider-call span (Chad's probe: 120 instead of 0).
- MAJOR-2: the budget property test now runs on a virtual-time event loop (`tests/virtual_time.py`), so tools, policies and verifiers really sleep and the loop's `asyncio.timeout` really cancels them, with no real waiting. Its strategy adds slow and hanging policy calls and verifiers, a tool that always times out, unparseable replies with token usage, and an optional step timeout. It asserts every budget invariant: `elapsed_s <= deadline_s + DEADLINE_TOLERANCE_S` (named constant, float rounding only), tokens equal to the sum of completed calls' usage and `<= max_tokens + largest single call`, and repairs `<= max_repairs + 1`. `test_deadline_budget` now checks the third call is cut at exactly 2.5 s, not an overshoot to 3.0 s.

### Added (M2 tracing and CLI)
- M2: run tracing (`agentic_research.agent.tracing`, ADR-0008). `AgentLoop.run_traced(task, provider=, model=, tool_format=, started_at=)` returns the final `RunState` plus a validated trace v1: a `run` root span (status, answer or classified error, budget usage and limits, `parse_failures` derived from the provider spans; `budget_exhausted`/`abstained` runs carry an event with the budget kind or reason), a `step` span per loop iteration that reached the policy (a failing last iteration included), a `provider_call` span per call the policy reports, and a `tool_call` span per executor attempt (retries included; a call rejected before running is a zero-length attempt 1). Verifier rejections (`answer_rejected`), loop guardrails (`loop_detected`) and retries the deadline cut off (`tool_not_retried`) are step events. `run()` is the same loop without the trace. Arguments or outputs JSON cannot represent (NaN, infinity) are replaced by a marker instead of failing the run. Provider-call spans cover the whole policy call; M2 policies make at most one call per step.
